# 질문 유형 타당성 실험 계획

작성 2026-08-29. 팀 회의 액션 아이템: 벤치마크들이 나눠 둔 질문 유형(HaluMem QA 6종,
BEAM probing 10종, Memora task 3종)이 실제로 서로 다른 메모리 능력을 분리해서 재는지,
이미 뽑아 둔 실험 산출물만으로(추가 LLM 인퍼런스 없이) 수치로 확인함.
종합 분석 계획(analysis-plan.md)의 T1(벤치마크마다 다른 순위)을 깊게 파는 실험이기도 함.

## 0. 검증할 주장

회의에서 나온 의심: "유형이 명시돼 있어도 실제 질문을 보면 명확히 분리되지 않거나
연관된 질문이 많다" (예: Multi-hop Reasoning 라벨인데 Knowledge Update 능력도 요구).
이것을 네 개의 검증 가능한 질문으로 쪼갬:

| | 질문 | 분석 |
|---|---|---|
| Q1 | 문항이 라벨 밖의 능력을 함께 요구하는가 | §2 요구 능력 태깅 |
| Q2 | 같은 유형의 문항들이 실제로 같은 방식으로 성공·실패하는가 | §3 문항 행동 군집 |
| Q3 | 유형 점수들이 서로 다른 것을 재는가 (사실상 몇 차원인가) | §4 프로파일 상관·차원 |
| Q4 | 유형이 시스템 비교에 정보를 더하는가 / 같은 이름이 벤치마크를 건너 일치하는가 | §5 상호작용 · §6 이식성 |

관측 자료 분석이므로 결론의 형태는 "능력 A와 B는 같은 능력이다"가 아니고
**"현 시스템들에 대해 이 벤치마크의 유형 구분은 분리에 성공/실패한다"** 임.
이 한계는 §8에 명시하고 보고 문구에도 그대로 씀.

## 2. 분석 1 · 요구 능력 태깅 (HaluMem, Q1)

회의에서 나온 예시를 그대로 수치화함. 문항마다 evidence 골든을 memory_points 에
조인해 세 가지를 태깅함 (전부 텍스트 조인, 인퍼런스 없음):

- **갱신 연루**: evidence 골든이 update 사건(is_update=True 연쇄)의 산물인가
- **다중 근거**: evidence 골든이 2개 이상인가 (여러 기억을 이어야 하는 문항)
- **미끼 인접**: 같은 세션에 interference 골든이 있는가

산출 메트릭 (유형 × 태그 교차표):

- 유형별 갱신 연루율. 예상 사용례: "Multi-hop 라벨 문항의 X%가 갱신 연루라서
  Dynamic Update 와 요구 능력이 겹침"
- 유형별 다중 근거율. "Basic Fact Recall 인데 다중 근거인 문항 Y%"
- 태그 조합의 유형 간 중복도 (같은 태그 조합이 여러 유형에 걸치는 비율)

이 분석은 시스템 성능과 무관하게 **문항 자체의 요구**를 재므로, 뒤 분석들의
행동 기반 결과와 독립인 두 번째 증거 줄기가 됨. BEAM 은 데이터셋에 골든 참조가
없어 이 분석은 HaluMem 한정임.

## 3. 분석 2 · 문항 행동 군집 (Q2)

같은 유형의 문항이 정말 한 덩어리로 움직이는지, 문항 단위 결과 벡터로 봄.

- 결과 벡터: HaluMem = 시스템 3벌의 정오(+C/H/O 원핫 확장판). BEAM 100K =
  (시스템, 프롬프트, cutoff) 실측 존재 조합의 점수 벡터 16차원
- 메트릭:
  - **유형 내 vs 유형 간 벡터 유사도 격차** + 순열검정 p (라벨 섞기 1만 회)
  - 무라벨 군집(계층·k-means) 대 라벨의 일치도: ARI·NMI
  - 유형별 내적 일관성 (조건들을 문항 "채점자"로 보는 KR-20 유사 지표)
- **주제 난이도 통제**: BEAM 은 대화별 평균을 뺀(within-conversation centering)
  판을 병기함. 같은 대화의 문항이 함께 어려운 효과가 유형 무관 상관을 만들기 때문

해석 기준: 유형 내 유사도가 유형 간과 다르지 않으면(p 크면), 그 유형 라벨은
문항의 행동을 설명하지 못하는 것임.

## 4. 분석 3 · 능력 프로파일 상관과 차원 (Q3)

조건 × 유형 점수 행렬을 만들고 유형 열들끼리의 구조를 봄.

- 조건 정의: BEAM = (시스템 × 스케일 × 프롬프트 × cutoff) 실측 존재 조합 약 36벌.
  HaluMem = 시스템 3 + 백본 그리드 런들 (런 안에서 z-정규화; 동일 judge 부분집합으로
  민감도 재검)
- 메트릭:
  - 유형 간 Spearman 상관 히트맵
  - **PCA 설명분산**: 제1·2주성분이 몇 %를 먹는가. "10개 능력이 사실상 몇 개인가"의
    직접 수치. 제1주성분 하나가 80~90%면 유형 구분이 시스템 변별에 거의 1차원
  - 유형 덴드로그램 (상관 거리 계층 군집): 어떤 유형끼리 한 묶음인지
- ⚠ cutoff 4벌은 중첩 검색이라 독립 조건이 아님. cutoff 를 접은(평균) 판을
  반드시 병기하고, 유의성은 대화 단위 블록 부트스트랩으로 냄

## 5. 분석 4 · 시스템 × 유형 상호작용 (Q4 앞부분)

유형 나눔이 시스템 비교에 정보를 더하는지 검정함. 모든 유형에서 시스템 우열이
같은 방향·같은 폭이면, 유형을 나눠 봐도 시스템에 대해 새로 알게 되는 것이 없음.

- HaluMem: 시스템쌍별 × 유형별 오즈비 + **Breslow-Day 동질성 검정**. 유형별
  대응 McNemar (repo 해석 원칙: 같은 문항을 여러 시스템이 푸므로 대응표본 검정)
- BEAM: 능력별 점수차 부호 일관성 + 순열검정
- 이질적인 유형(예: HaluMem Dynamic Update 의 v3 우위 +5.0p)만 골라
  "이 유형은 실제로 변별력이 있다"로 분류함

## 6. 분석 5 · 벤치마크 간 같은 이름 능력의 이식성 (Q4 뒷부분)

같은 능력을 재겠다고 이름 붙인 유형이 벤치마크를 건너 같은 시스템 순위를 내는지 봄.

대응표 (이름·정의 기준):

| HaluMem | BEAM | Memora |
|---|---|---|
| Dynamic Update | knowledge_update | (없음) |
| Multi-hop Inference | multi_session_reasoning | reasoning |
| Basic Fact Recall | information_extraction | remembering |
| Memory Boundary | abstention | (없음) |
| Memory Conflict | contradiction_resolution | (없음) |

- 메트릭: 대응 능력별 시스템 순위 일치(Kendall τ, 쌍별 부호 일치율). 노이즈
  바닥(±2.2%p 수준) 안의 차이는 동률 처리
- **사전 확인에서 이미 불일치가 나옴** (2026-08-29 실측, BEAM 은 100K 공식
  프롬프트 cutoff 50):
  - "모른다고 하기": HaluMem Memory Boundary 는 v3 우위(82.1 vs 80.8)인데
    BEAM abstention 은 classic 큰 우위(42.5 vs 25.0). **방향이 뒤집힘**
  - "상충 처리": HaluMem Memory Conflict 는 classic 근소 우위(81.7 vs 80.9)인데
    BEAM contradiction_resolution 은 v3 우위(8.4 vs 5.6). 역시 반대 방향
    (단 BEAM 쪽은 능력당 40문항이라 폭이 작으면 노이즈 가능)
  - "갱신 반영"은 두 벤치마크가 방향 일치 (v3 ≥ classic): HaluMem +5.0,
    BEAM +1.2
- 본 분석에서는 이것을 전 대응쌍 × 전 시스템쌍으로 확장하고 유의성을 붙임

## 7. 선택 확장 (본 계획 밖, 별도 결정)

- **질문 임베딩 분리도** (LLM 없음, 8001 임베더 ~4.6k콜): 유형별 실루엣, k-NN
  라벨 순도, 유형 교차 최근접 이웃 목록. 문항의 "겉모습"이 유형을 구분하는지와
  겹치는 질문 쌍의 정성 사례를 얻음
- **다중 라벨 재판정** (LLM ~4.3k콜, 자체 vLLM 약 1시간): 문항마다 요구 능력
  집합을 다중 선택으로 재라벨링해 라벨 중복률을 직접 측정. 가장 직접적이지만
  판정 LLM 의 관점이 개입하므로 관측 분석과 분리해서 보고해야 함

## 8. 해석할 때 지킬 것

- 상관·군집은 "현 시스템 집합(mem0 두 벌 + LIGHT)에 대한 분리 실패"의 증거이지
  능력 동일성의 증명이 아님. 시스템이 3개뿐이고 전부 검색 + LLM 독해라는 공통
  병목을 공유함. 공통 병목이 만드는 겉보기 상관은 대화 고정효과 제거(§3)와
  cutoff 반응 곡선 비교로 부분 통제함
- 작은 유형(HaluMem Dynamic Update 180, BEAM 능력당 40)은 재실행 편차가 큼.
  유의성은 순열검정으로 내고 다중비교는 BH 보정
- 절대 수치는 judge 선택에 지배됨. 조건 확장에 옛 그리드 런을 쓸 때는 런 안
  z-정규화 + 동일 judge 부분집합 재검을 반드시 함
- 유형별 문항 수가 달라 전체 점수는 유형 구성비의 함수임 (T1). 이 실험의 산출이
  곧 T1 카드의 사례 근거가 됨

## 9. 대시보드 반영

계산은 `src/analysis/ability_validity.py` 가 하고 산출 JSON 을
`results/exports/ability-validity.json` 으로 떨굼. 대시보드는 읽기만 함
(요청마다 통계를 돌리지 않음). 화면은 새 상단 탭 **"유형 타당성"** 에 카드 4벌:

1. 요구 태깅 표: 유형 × (갱신 연루율 · 다중 근거율 · 미끼 인접율), HaluMem
2. 능력 상관 히트맵 + PCA 설명분산 막대, BEAM·HaluMem 각각
3. 시스템 × 유형 상호작용 표: 유형별 오즈비와 동질성 검정, 변별력 있는 유형 강조
4. 벤치마크 간 이식성 표: 대응 능력 × 시스템쌍의 방향 일치/불일치 (§6 대응표 기준)

모든 표는 기존 규약대로 `table.cmp` 상호작용, 시스템 줄에는 `data-sysi` 색 띠.
