# 심층 분석: 3 벤치마크 × 3 메모리 시스템, 수치와 기제

작성 2026-08-31. 대상: HaluMem-Medium 20유저 · BEAM 100K/500K · Memora weekly/monthly,
시스템은 mem0 classic 0.1.118 · mem0 v3 2.0.18 · LIGHT(BEAM 3e12035 이식).
전부 같은 조건(agent gpt-oss-120b medium / 답변·채점 gpt-oss-120b high /
Qwen3-Embedding-4B 2560d). 모든 수치는 이 날짜에 산출물에서 직접 재집계한 값이고,
표본 판독(§2)은 실제 문항·답변·컨텍스트를 열어 확인한 것임.

분석 도구: `src/analysis/deep_probe.py`(기제 3종) ·
`src/analysis/ability_validity.py`(유형 타당성 B1~B5) ·
`src/analysis/question_diff.py`(문항 대조). 산출 json 은 `results/exports/`.

## 0. 요약

1. **순위는 벤치마크가 아니라 "질문이 슬롯에게 무엇을 요구하는가"가 정함.**
   같은 3 시스템이 HaluMem QA 에서는 LIGHT 1등, Memora 전체에서는 LIGHT 꼴찌,
   BEAM 에서는 답변 프롬프트에 따라 1등이 바뀜. 기제 분석 결과 이 셋은 하나의
   변인으로 수렴함: **메모리 슬롯 하나에 원문을 담는가(LIGHT), 원자화한 사실을
   담는가(mem0)**. 단일 사실 회수는 원문 보존이 이기고, 전수 열거·집계는
   원자화가 이김 (§2-1).
2. **저장 지표는 태스크 성능을 예측하지 못함.** 추출 F1 이 12.7 → 32.6 으로
   2.6배 벌어진 classic 대 v3 의 QA 는 동률(문항 수준 상호작용 검정도 동질,
   Woolf Q=2.53). 미끼 차단 12.2 로 최하위인 LIGHT 가 QA·환각률 모두 최선 (§2-3).
3. **갱신 능력 채점의 상당 부분은 갱신이 아니라 축자성(verbatim)을 잼.**
   갱신 문항 불일치 표본에서 낡은 값을 답한 실패는 소수였고, 다수는 의미가
   맞는 답을 골든의 상태 라벨 표현과 다르다는 이유로 H/O 처리한 것 (§2-2).
4. **답변 프롬프트가 시스템 간 격차와 순위를 바꿈.** 같은 투입·같은 검색에서
   프롬프트만 바꾸면 classic 대 v3 격차가 +1.9p 에서 +5.2p 로, 1등이 LIGHT 에서
   v3≈LIGHT 로 바뀜 (§2-4).
5. **질문 유형 분류는 부분적으로만 실재함.** 유형 내 문항 응집은 전체로는
   유의하지만(p=0.0005) 절반의 라벨에서만 성립하고, knowledge_update ·
   event_ordering · preference_following 라벨은 문항 행동을 전혀 설명하지 못함.
   10개 능력의 실효 차원은 2~3개(PC1 56~62%) (§3).
6. **배포 비용은 정확도 표의 뒷면임.** LIGHT 의 HaluMem QA +4.8p 는 LLM 호출
   74배·입력 토큰 23배의 값임 (§4).

## 2. 기제 분석 (수치 + 표본)

### 2-1. 슬롯의 내용물이 승부를 가름: 원문 보존 vs 원자화

**가설**: LIGHT 의 HaluMem QA 우위와 Memora reasoning 참패는 같은 설계
선택(검색 결과로 원문 pair 를 그대로 돌려줌)의 양면이다.

**검증 1 — 근거 도달률** (`deep_probe` A1, Memory Boundary 제외 2,639문항).
골든 답변의 재료가 답변 컨텍스트에 실제로 실렸는가(토큰 70% 관대 매칭):

| | 도달률 | 도달 시 정답률 | 미도달 시 정답률 |
|---|---|---|---|
| classic | 49.7% | 67.4% | 47.7% |
| v3 | 64.5% | 68.8% | 39.4% |
| LIGHT | **89.9%** | 64.5% | 52.6% |

도달했을 때의 정답률은 세 시스템이 64~69%로 비슷함. 즉 **차이는 독해 단계에
있지 않고 전달 단계에 있음.** 추출 파이프라인은 사실을 바꿔 쓰거나 버려서
재료의 절반~1/3을 잃고, 원문 반환은 거의 다 실어 나름.

**검증 2 — 열거 집계의 붕괴 지점** (Memora monthly reasoning, LIGHT 3.00).
표본 6건을 열어 보니 실패 형태가 동일함: "이번 달 커피 지출 총액은?"
($255.17 정답 요구) 류의 **전수 집계** 질문에서 LIGHT 는 성실하게 표까지
그리며 합산하지만 항목이 모자람. 같은 질문에서 컨텍스트 50슬롯의 내용을 세면:

- v3: coffee 언급 47항목 · 금액 **42종** (슬롯 하나 = 증류된 사실 한 줄)
- LIGHT: coffee 언급 28항목 · 금액 **26종** (슬롯 하나 = 대화 pair 통째)

같은 50슬롯 예산에서 원자화는 관련 사실을 촘촘히 싣고, 원문은 슬롯을
통째로 먹어 커버리지가 반토막 남. v3 의 monthly reasoning 고득점 12건이
전부 이 열거형이고 LIGHT 는 0.8 이상이 0건임. **추출은 열거형 질문에 대한
사전 계산으로 기능함.**

덧붙여 시간 좌표 문제가 겹침: LIGHT 는 원본 충실 재현이라 Memora pair 에
날짜를 안 넣었고(공식 조건과 동일), "몇 주차에 가장 많이 썼나" 질문에서
스스로 "메모리에 날짜가 없어 특정할 수 없다"고 답함. v3 는 추출문 안에
날짜가 섞여 들어가는 경우가 있어 부분적으로 우회함. 이 몫은 설계 차이가
아니라 시간 정보 배치 차이이므로, 분리하려면 LIGHT 에 시각 접두를 켠
대조군 재실행이 필요함 (§6).

**검증 3 — 축자성 이득.** LIGHT 의 강한 유형이 Basic Fact Recall(+11p)인
것도 같은 기제임. 골든 답변이 "1984-06-16" 같은 정확한 값이고, 원문 pair 는
그 표현을 그대로 보존함. 추출은 바꿔 써서 잃음 (A1 strict 포함률: LIGHT
24.8% vs mem0 12.7~13.5%).

### 2-2. 갱신 채점의 실체: 낡은 값 검출이 아니라 표현 일치 검사에 가까움

Dynamic Update 180문항 중 시스템 간 정오가 갈린 116건을 덤프해
(`/tmp/du_disagreements.txt`) 표본 판독함. 두 부류가 섞여 있음:

- **진짜 갱신 실패** (낡은 값을 답함): 소수. 예: "career status?" 골든
  "Retired and working as a Mentor" 에 classic "Still working as a director",
  v3 "Lead director". LIGHT 도 "Stable mental health"(갱신 전 값) 사례 있음.
- **표현 불일치를 실패로 채점**: 다수. 예: 골든 "Retired and working as a
  Mentor and Advisor" 에 LIGHT "Mentor, retired from active filmmaking" →
  **누락(O) 판정**. 골든 "Executive Director at Huaxin Consulting" 에
  "Executive Director"(회사명 누락) → O. 골든 "Empowerment and satisfaction"
  에 "Empowered and optimistic" → H.

HaluMem 의 갱신 골든이 "Abnormal", "Below Average" 같은 **상태 라벨**이라,
채점이 사실상 그 라벨의 재현 여부를 물음. 그래서 이 유형에서도 원문을
보존하는 LIGHT 가 이김(49.4). 갱신 반영 능력의 순수한 측정으로 읽으면 안 됨.

같은 이름의 능력이 벤치마크를 건너면 순위가 뒤집히는 것도 이와 정합함:
갱신 반영은 HaluMem 에서 LIGHT 1등(49.4/45.0/40.0), BEAM knowledge_update
에서는 LIGHT 꼴찌(40.6/46.2/45.0). 두 벤치마크가 "갱신"이라는 말로 서로
다른 것을 재고 있음.

### 2-3. 미끼(interference) 지표와 실제 간섭의 어긋남

LIGHT 는 거르지 않고 다 저장해서 미끼 차단이 12.2(최하)임. 그런데 답변
단계에서는 (`deep_probe` A2, 미끼 세션 1,327개 = QA 의 95%):

| | 미끼 재료가 컨텍스트에 유입 | 미끼 세션 환각률 | 미끼 세션 정답률 |
|---|---|---|---|
| classic | 57.3% | 21.0 | 61.5 |
| v3 | 94.1% | 21.1 | 62.6 |
| LIGHT | **100.0%** | **19.2** | **66.5** |

미끼 재료가 컨텍스트에 가장 많이 들어가는 LIGHT 의 환각률이 가장 낮음.
즉 **저장소에 미끼가 남아 있는 것(미끼 차단 지표가 재는 것)과 답변이
미끼에 홀리는 것(실제 간섭)은 다른 사건임.** 답변 LLM 이 질문 관련성으로
미끼를 스스로 걸러냄. 미끼 차단 지표는 미끼를 겨냥한 검색으로 저장소를
찌르는 측정이라, 배포 상황의 간섭 위험을 과대 표현함.

### 2-4. 답변 프롬프트 × 시스템 상호작용

같은 투입·같은 검색 결과에서 답변 프롬프트만 바꾼 두 자리(BEAM 100K):

| 전체 평균 | classic | v3 | LIGHT | 1등 |
|---|---|---|---|---|
| BEAM 공식 (답만 간결히) | 40.47 | 42.39 | 44.97 | LIGHT |
| mem0 하네스 (서술형) | 52.58 | 57.81 | 57.71 | v3 ≈ LIGHT |

격차(classic 대 v3)가 +1.9p → +5.2p 로 2.7배가 되고 순위도 바뀜. 프롬프트
효과가 시스템마다 다르게 먹기 때문임(상호작용). 단 능력 수준에서 일관된
것도 있음: abstention 은 두 프롬프트 모두 classic 우위(46.2/44.4 vs v3
33.1/25.6, LIGHT 34.4/24.4)라 프롬프트 탓이 아님. 발표되는 벤치마크 점수가
답변 규약이라는 보고서 밖 변인에 얹혀 있다는 실증임 (2026-08-26 부호 뒤집힘
사고 −10.19 → +1.93 과 같은 계열).

## 3. 질문 유형 분류의 타당성 (ability-validity B1~B5)

**B1 · 문항이 라벨 밖 능력을 요구함.** evidence 골든을 갱신·미끼 사건에
조인한 결과(문항 자체의 요구, 시스템 무관):

| 유형 | 다중 근거율 | 갱신 연루율 |
|---|---|---|
| Basic Fact Recall | 5.2% | **65.4%** |
| Dynamic Update | 38.9% | 81.1% |
| Generalization & Application | **92.8%** | 65.4% |
| Memory Boundary | 0.0% | 0.0% |
| Memory Conflict | 59.9% | 64.4% |
| Multi-hop Inference | 97.5% | **78.8%** |

회의에서 나온 의심 그대로임: Multi-hop 문항의 78.8%가 갱신 연루라
Dynamic Update 와 요구가 겹치고, "기본 회수"조차 65%가 갱신된 값을 물음.
갱신 연루가 전 유형에 64~81%로 깔려 있어 **어떤 유형도 갱신 능력을
분리해서 재지 못함.**

**B3 · 행동 응집은 절반의 라벨에서만 성립.** BEAM 100K 400문항을
(시스템×프롬프트×cutoff) 24차원 결과 벡터로 놓고 유형 내 vs 유형 간
유사도를 재면 전체 격차 +0.076 (순열 p=0.0005). 그러나 유형별로는:
contradiction_resolution(+0.49) · summarization(+0.17)은 강하게 응집,
**knowledge_update · event_ordering · preference_following 은 음수**
(같은 라벨 문항끼리가 남남보다 다르게 행동함).

**B2 · 실효 차원은 2~3개.** 조건 48벌 × 능력 10종 행렬의 PCA: PC1 56.1%
PC2 19.2% (cutoff 접은 판 62.1/19.3). 능력 간 Spearman 상관 중앙 0.317,
범위 −0.68~+0.77. 전부 같은 것도 아니고(1차원 아님) 10개가 다 다른 것도
아님.

**B4 · 유형이 시스템 비교에 주는 정보는 비대칭.** classic 대 v3 는 유형별
오즈비가 동질(Woolf Q=2.53, df=5)이라 유형 분해가 아무 정보도 더하지 않음.
classic·v3 대 LIGHT 는 이질(Q=19.4·21.9 > 임계 11.07)이고 그 이질성의
대부분이 Basic Fact Recall(McNemar χ² 32~35) 하나에서 옴.

**B5 · 같은 이름이 벤치마크를 건너 일치하지 않음** (classic/v3/LIGHT):

| 능력 | HaluMem | BEAM | Memora |
|---|---|---|---|
| 갱신 반영 | 40.0/45.0/**49.4** | 45.0/**46.2**/40.6 | |
| 다중 결합 | 36.4/39.4/38.9 (동률권) | 31.7/**45.7**/41.8 | 15.7/**39.3**/12.8 |
| 사실 회수 | 59.2/59.4/**70.4** | 55.5/67.2/**75.9** | 59.5/44.5/**59.8** |
| 모른다고 하기 | 80.8/82.1/82.5 (동률권) | **42.5**/25.0/30.0 | |
| 상충 처리 | 81.7/80.9/81.0 (동률권) | 5.6/8.4/7.2 (바닥권) | |

갱신 반영과 모른다고 하기는 방향이 뒤집히고, 상충 처리는 한쪽에서 81 다른
쪽에서 6이라 측정 자체가 다른 것을 봄. 유일하게 이식되는 것은 사실
회수의 LIGHT 우위 정도임.

## 4. 배포 비용 (LLM 호출만, 채점 제외 · 계측/backfill 완비 행)

| 세팅 | classic | v3 | LIGHT |
|---|---|---|---|

| Memora monthly | 10,705콜 · 14.7M입력 | (투입 미계측) | 120,226콜 · 81.0M입력 |

- LIGHT 의 HaluMem QA +4.8p 는 **호출 74배 · 입력 토큰 23배**의 값임
  (pair 단위 투입 + 질의마다 조각별 필터 콜). 정확도 표만 보면 이 자릿수
  차이가 통째로 안 보임.
- v3 는 호출이 classic 의 절반(1콜 ADD-only)인데 입력 토큰은 2.5배임
  (거대한 추출 프롬프트). 호출 수와 토큰량이 반대로 움직이므로 단가 축을
  나눠 봐야 함.

## 5. 문제 카드

### 카드 1 · 벤치마크 점수는 "기억력"보다 슬롯 규약을 잰다

- **현상**: 세 벤치마크의 순위 역전이 슬롯 내용물(원문 vs 원자화) 하나로
  대부분 설명됨.
- **수치·표본 근거**: §2-1 (도달률 89.9 vs 49.7~64.5 · 커피 42종 vs 26종 ·
  축자성 사례).
- **반례 검토**: "LIGHT 가 그냥 좋은 시스템"이라는 설명은 Memora reasoning
  3.00 과 BEAM knowledge_update 꼴찌로 기각. "벤치마크 난이도 차이"는 같은
  벤치마크 안 유형별 역전(B4)으로 기각.
- **Problem statement**: 벤치마크와 시스템 양쪽의 문제임. 벤치마크는 질문
  구성비로 슬롯 규약 하나를 보상하거나 처벌하면서 그것을 "기억 능력"으로
  보고하고, 시스템은 한 규약을 고정해 반대편 질문군을 구조적으로 포기함.
- **연구 질문**: 기억의 보관 형태(원문·원자 사실·요약)와 질문의 요구(단일
  회수·전수 열거·시점 판정) 사이의 적합성을 1급 변인으로 삼는 평가·설계
  이론이 가능한가. 저장 시점에 무엇을 미리 계산할지 알 수 없다는 내생성
  문제와 어떻게 만나는가.
- **요구하는 것**: 질문 요구 명세가 붙은 벤치마크 설계 + 혼합 보관(원문과
  원자화 병행) 시스템 부류.

### 카드 2 · 저장 지표와 태스크 지표는 분리돼 있다

- **현상**: F1 2.6배(12.7→32.6) 차이가 QA 동률로, 미끼 차단 최하(12.2)가
  QA 최선으로 이어짐.
- **수치 근거**: §1 성적표, §2-3 (미끼 유입 100%인데 환각률 최저), B4
  (classic 대 v3 전 유형 동질).
- **반례 검토**: "QA 가 저장과 무관한 쉬운 문항"이라는 설명은 미끼 세션
  정답률 61~66 (그 외 92)로 기각 — 어렵고, 저장물에 실제로 의존함.
- **Problem statement**: 벤치마크의 중간 지표(저장물 품질·미끼 차단)가
  최종 태스크의 예측자가 아님. 특히 미끼 차단은 미끼 겨냥 검색이라는
  비현실 부하로 잼.
- **연구 질문**: 태스크 성능을 실제로 예측하는 저장물의 측정 가능한 속성이
  존재하는가. §2-1 의 "근거 도달률" 같은 전달 단계 지표가 그 후보인가.
- **요구하는 것**: 저장-검색-전달-독해를 단계별로 분리 측정하는 평가 설계.

### 카드 3 · 갱신 평가가 갱신을 재지 못한다

- **현상**: 무갱신 시스템(LIGHT)이 HaluMem 갱신 유형 1등, BEAM 같은 이름
  능력에서는 꼴찌. 불일치 표본의 다수가 표현 불일치 채점.
- **수치·표본 근거**: §2-2, B1 (갱신 연루가 전 유형 64~81%라 분리 측정
  불가), B5 방향 뒤집힘.
- **Problem statement**: 갱신·철회 능력을 잰다는 지표들이 실제로는 (a) 상태
  라벨 축자 재현(HaluMem), (b) 정의 불명의 혼합물(BEAM)을 재고 있음.
- **연구 질문**: 기억의 철회·개정이 실제로 필요한 순간을 만들어내고, 그
  성패를 표현이 아니라 값의 시점 정합성으로 채점하는 평가는 어떻게
  설계하는가 (다섯 난제의 철회·지위 문제의 평가판).

### 카드 4 · 점수는 실험 절차의 함수다

- **현상**: 답변 프롬프트 하나로 격차 2.7배·순위 교체 (§2-4). 재실행 편차
  ±2.2p, 투입 반복 편차 대화 단위 최대 11.1%.
- **Problem statement**: 발표 수치의 상당 부분이 보고서에 안 적히는 절차
  변인(답변 규약·judge 성향)에 얹혀 있고, 그 민감도가 시스템 간 격차와
  같은 자릿수임.
- **연구 질문**: 메모리 벤치마크의 재현 규약(무엇을 고정하고 무엇을 함께
  보고해야 하는가)이 없는 상태에서 리더보드 축적은 무엇을 축적하는가.

### 카드 5 · 질문 유형 분류는 절반만 실재한다

- **현상**: 응집 라벨과 무의미 라벨이 공존(B3), 실효 차원 2~3개(B2), 요구
  능력 중첩(B1), 벤치마크 간 비이식(B5), 시스템 변별 기여는 특정 비교·특정
  유형에 국한(B4).
- **Problem statement**: 유형 분류가 휴리스틱하다는 팀 의심의 수치 확인.
  단, "전부 무의미"가 아니라 **부분 실재**가 정확한 결론임 — 분류를 버릴
  것이 아니라 검증된 라벨만 남기고 요구 명세(다중 근거·갱신 연루 등 태깅
  가능한 속성)로 재구성할 근거가 생김.
- **연구 질문**: 능력 라벨 대신 문항의 측정 가능한 요구 속성(근거 수, 갱신
  연루, 시점 제약, 열거 범위)으로 벤치마크를 명세하면 시스템 간 비교가
  이식 가능해지는가.

### 카드 6 · 비용 없는 리더보드는 절반의 표다

- **현상·근거**: §4. +4.8p 에 74배 호출.
- **연구 질문**: 같은 토큰 예산 아래의 비교(iso-cost)가 표준이 되어야
  하는가. 시스템마다 다른 투입 단위는 존중할 설계 철학인가 통제할 교란인가.
