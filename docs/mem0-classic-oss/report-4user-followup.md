# 후속 보고: 4유저 확장 결과 (2026-07-31)

> 앞서 "1유저 결과라 유저를 늘리면 양상이 뒤바뀔 수 있다"고 예고했던 부분의 후속입니다.
> Generator·Judge는 그대로 GPT-OSS-120B(high), **Agent 실험(Stage A)은 재실행하지 않았고 답변 생성과 채점만 4유저로 확장**했습니다. 12개 조합 전부, 총 705문항. 채점 무효율 0.078%.

---

## 요약 세 줄

1. **QA 1위는 GPT-OSS-120B로 바뀌었지만, 2·3위와의 차이는 통계적으로 무의미합니다.** 순위 변동은 실현됐고, "상위권은 구분 불가"라는 판단도 그대로 유지됩니다.
2. **완전히 같은 설정으로 답변만 다시 생성했더니 판정의 21%가 바뀌었습니다.** 이번 데이터에서 가장 중요한 발견이며, 지금까지 우리가 비교해온 모든 "수 %p 차이"에 이 단서가 붙어야 합니다.
3. **프롬프트(Custom) 효과는 더 견고해졌습니다** — 6개 백본 전부에서 같은 방향으로 작동합니다.

## 1. QA 순위: 바뀌었으나 유의하지 않음

1유저에서 58.54로 3위권이던 GPT-OSS-120B가 4유저에서 **61.28로 1위**가 됐습니다. 다만 문항 단위로 McNemar 검정을 해보면 상위 3개는 서로 구분되지 않습니다.

| GPT-OSS-120B 대비 | 정답 수 (705문항 중) | p값 | 판정 |
|---|---|---|---|
| GPT-5-Nano | 432 vs 419 | 0.280 | **구분 불가** |
| GPT-5-Mini | 432 vs 414 | 0.150 | **구분 불가** |
| Qwen3-30B | 432 vs 396 | 0.005 | 유의 |
| Qwen3-4B-Thinking | 432 vs 389 | 0.001 | 유의 |
| Qwen3-4B-Instruct | 432 vs 356 | <0.001 | 유의 |

즉 **상위 3개 그룹의 구성원만 (Nano·Mini·30B) → (OSS-120B·Nano·Mini)로 교체**됐고 Qwen3-30B가 탈락했습니다. 표본을 4배로 늘려도 1·2위 사이 p=0.28이므로, **QA Correct 몇 %p 차이로 우열을 말하지 않는다**는 기존 원칙은 유지합니다.

## 2. ⚠ 같은 설정으로 다시 돌리면 판정의 21%가 바뀝니다

1유저 데이터와 4유저 데이터는 **설정이 완전히 동일합니다.** 같은 메모리(Stage A 산출물 재사용), 같은 Generator, 같은 Judge. 달라진 것은 답변 생성을 한 번 더 돌렸다는 것뿐입니다. 그런데 같은 유저(Martin)의 같은 문항에서 **판정이 21.0%(1,968건 중 413건) 바뀌었습니다.**

무엇을 뜻하는가:

- **조합 간 QA 점수의 몇 %p 차이는 재실행만으로도 생길 수 있습니다.** 앞으로 절대 수치를 인용할 때 이 변동폭을 함께 적어야 합니다.
- 지난번에 공유드린 **"모든 조합이 실패한 15문항" 중 7개가 재실행만으로 해소**됐습니다(46%). 두 번 모두 전부 실패한 진짜 난공불락은 **8문항**입니다. 정성분석 우선순위는 이 8개에 두는 것이 좋겠습니다. (다만 벤치마크 결함으로 지목한 3문항은 "대화에 정답 근거가 아예 없다" 같은 개별 근거로 판정한 것이라 그대로 유효합니다.)
- 이 21%에는 **답변 생성의 변동과 채점의 변동이 섞여** 있습니다. 둘을 분리하려면 한쪽을 고정하고 반복 측정해야 하며, 이는 지금 준비 중인 **Judge 품질 정량화 과제의 첫 번째 설계 항목**으로 삼겠습니다.

## 3. QA 성능을 좌우하는 것: "넓게" + "깨끗하게"

12개 조합에서 각 지표와 QA Correct의 순위상관(스피어만)을 봤습니다. 괄호는 1유저 값입니다.

| 지표 | QA와의 상관 |
|---|---|
| Weighted Recall − Recall 격차 (= 부분 포함의 양) | **+0.88** (+0.78) |
| **Accuracy (저장 청결도)** | **+0.75** (+0.42) |
| Target Precision | +0.69 (+0.50) |
| 저장한 메모리 수 | +0.67 (+0.55) |
| **Recall (완전 포함 비율)** | **−0.15** (+0.16) |
| FMR (미끼 저항) | −0.30 (−0.52) |

- **Recall은 QA와 사실상 무관합니다.** 4유저에서도 그대로이고 부호까지 뒤집혔습니다(= 노이즈 수준).
- 대신 **"부분적으로라도 넓게 저장했는가"(격차 +0.88)**와 **"저장한 것이 깨끗한가"(Accuracy +0.75)**가 QA를 끌어올립니다. Accuracy는 1유저에서 중간이었는데 4유저에서 크게 부상했습니다.
- 실무적 함의: 골든을 온전히 담으려 애쓰는 것보다, **부분적이라도 넓게 그리고 근거 있게 저장**하는 쪽이 답변 성능에 유리합니다.

## 4. Custom 프롬프트: 6개 백본 전부에서 동일한 트레이드오프

1유저에서 유일한 예외였던 Qwen3-4B-Instruct(QA +2.4)가 4유저에서 −0.4로 바뀌면서, **QA Correct 하락이 6/6**이 됐습니다. 나머지 방향성도 그대로입니다.

| 지표 | default → custom |
|---|---|
| Accuracy | **6/6 하락** (−21~−49%p) |
| Update Correct | **6/6 상승** (+6~+21%p) |
| Recall | 5/6 상승 (예외: 4B-Thinking) |
| FMR | 5/6 상승 (예외: 4B-Instruct) |
| **QA Correct** | **6/6 하락** |

프롬프트 효과는 백본 선택보다 일관되고 강합니다.

## 5. 참고: 유저별 난이도 편차가 큽니다

12개 조합이 모두 실패한 문항이 705문항 중 78개(11.1%)인데, **유저별로 10 / 18 / 25 / 25개로 편차가 큽니다.** 지금까지 분석해온 Martin Mark가 가장 쉬운 유저였습니다. 어느 하나라도 맞힌 문항의 합집합은 88.9%입니다.
